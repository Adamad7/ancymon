# AncyMon

**Distributed Workstation Telemetry & Monitoring System for Local Area Networks**

AncyMon is a high-efficiency, cross-platform telemetry monitoring platform designed for modern local area networks. It continuously streams granular hardware metrics from Linux and Windows workstations at 1 Hz, ingests and aggregates them into a centralized time-series database (VictoriaMetrics), and serves a mobile dashboard (Flutter) over real-time GraphQL WebSockets.

## Core Engineering Principles

* **Zero External Runtime Dependencies:** The host agent (`ancymon-agent`) compiles to a completely static, standalone binary (`CGO_ENABLED=0`) with zero dependencies on dynamic libraries, interpreters, or system daemons.
* **Network Partition Resilience:** In the event of a network outage, WiFi drop, or server reboot, telemetry is appended to an offline **Segmented Write-Ahead Log (WAL)** (1 MB segments, bounded by a 50 MB FIFO ceiling). The agent RAM footprint stays flat (~10–15 MB), and historical segments are drained in strict chronological order upon reconnection.
* **Active Connection Liveness:** Long-lived gRPC streams enforce strict HTTP/2 keepalive ping framing (30s ping / 10s timeout on client; 15s min / 60s server ping) to prevent silent drops across stateful NATs and firewall appliances.
* **Zero-Typing Onboarding UX:** Pairing a mobile phone requires scanning a terminal QR code generated by the server. The payload embeds connection parameters and raw Base64-encoded ECDSA P-256 root certificate bytes, dynamically injected into Dart's runtime `SecurityContext` without installing self-signed certificates into the OS trust store.
* **Dynamic Time-Series Rollups:** VictoriaMetrics downsamples telemetry dynamically in-flight using MetricsQL range queries (`/api/v1/query_range`), avoiding rigid background rollup jobs and maintaining smooth 100–300 point line charts across 1h, 6h, 12h, 24h, 3d, and 7d horizons.

## Quickstart: Local Test Environment

Spin up the local test environment using Docker Compose and run the Go services locally:

### 1. Launch Supporting Infrastructure
```bash
# Start VictoriaMetrics (:8428) and Caddy TLS Gateway (:443)
docker compose -f deploy/docker-compose.yml up -d

# Verify infrastructure health and TLS certificate negotiation
./deploy/test_vm.sh

# Extract Caddy's internal ECDSA Root CA for local clients
docker cp ancymon-caddy:/data/caddy/pki/authorities/local/root.crt deploy/root.crt
```

### 2. Start Central Telemetry Server
```bash
# Run server with local configuration
make -C server run
```

### 3. Generate Mobile Pairing QR Code
```bash
# In a new terminal window:
make -C server qr
```

### 4. Build and Run Workstation Agent
```bash
# Build static Linux agent binary
make -C agent build-linux

# Start agent in foreground pointing to local Caddy TLS gateway
./agent/bin/ancymon-agent run -config agent/config.example.yaml
```

For complete local testing details and clean teardown commands, see [`deploy/README.md#section-1-local-test--development-environment-docker-compose`](file:///home/mazad/Programowanie/ancymon/deploy/README.md).

## Quickstart: Production Deployment (Proxmox VE LXC)

In production, AncyMon runs inside a single unprivileged Debian 12 LXC container on Proxmox VE:

1. **Provision Container:** Create a Debian 12 LXC container (1–2 vCPUs, 512 MB–1 GB RAM, 10–20 GB disk) with a static LAN IP (e.g., `192.168.1.50`).
2. **Install VictoriaMetrics:** Download the single-node binary and register `victoriametrics.service` (`-retentionPeriod=90d`).
3. **Configure Caddy:** Install Caddy, configure `/etc/caddy/Caddyfile` with internal ECDSA P-256 automated CA (`tls internal`), and proxy to ports `50051` (h2c gRPC) and `8080` (GraphQL).
4. **Deploy ancymon-server:** Compile static binary with `CGO_ENABLED=0`, configure `/etc/ancymon/server.yaml`, and register `ancymon-server.service`.
5. **Deploy ancymon-agent on Workstations:**
   - **Linux:** Copy binary, configure `/etc/ancymon/agent.yaml`, and run `ancymon-agent install` to register as a native `systemd` daemon.
   - **Windows:** Copy binary, configure `config.yaml`, and run `.\ancymon-agent.exe install` in Administrator PowerShell to register as a native Windows Service.

For ready-to-use systemd unit files, Windows PowerShell commands, and troubleshooting guides, consult the [AncyMon Deployment & Operations Manual](file:///home/mazad/Programowanie/ancymon/deploy/README.md).

## Hardware Telemetry Specifications

The agent inspects hardware subsystems at a 1 Hz sampling cadence:

* **CPU:** Aggregate core utilization (%) and thermal sensor package temperature (°C, graceful null fallback on VMs).
* **RAM:** Total installed capacity, used memory, and percent utilization.
* **Network I/O:** Delta calculation across consecutive 1-second ticks reporting `rx_bytes/sec` and `tx_bytes/sec`.
* **Storage Partitions:** Dynamically discovered volumes filtered strictly against a filesystem whitelist (`ext4`, `xfs`, `btrfs`, `zfs`, `ntfs`, `vfat`, `fat32`, `apfs`) to omit virtual pseudo-mounts (`tmpfs`, `devtmpfs`, `overlay`).
